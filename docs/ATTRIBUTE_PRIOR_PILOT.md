# MC 形状先验与参考属性分支试验

本试验接续 [泛化与形状诊断](GENERALIZATION_20261102.md)，沿用冻结 Qwen3-8B。目的是验证减少参考图空间信息后，能否保留外观控制并减轻轮廓跟随；它不是已完成原版风格认证的新模型。

## 已实现的行为

`model.reference_encoding` 默认为 `spatial`，保持历史 v3 配置和权重的计算路径。设为 `dual` 后增加独立属性编码器和属性交叉注意力：

- 属性编码器仅使用逐像素 1×1 卷积，再汇总均值、方差和最大值为三个 token，不含坐标或邻域。它对像素排列不敏感，因此无法直接传递参考轮廓的位置结构。颜色占比仍可能与类别、形状相关，不能宣称完全消除了所有形状信息。
- 属性注意力的门初始为零，迁移时先保持旧模型输出；它与原有空间参考分支独立。
- `reference_mode="attributes"` 禁用参考空间 token，保留属性分支；`"shape"` 允许空间分支和属性分支共同参与。`ref_scale` 仍控制整个参考作用，并非独立的形状强度滑块。
- Runtime、CLI 和 API 共用路由：dual 检查点有有效文字条件时默认 attributes；纯图输入或文字强度为零时默认 shape。可显式覆盖。旧 spatial 检查点拒绝 attributes 模式。
- 纯图入口仍依赖参考几何，尚未加入类别识别器。无序统计无法完整保留局部纹理、花纹位置或精细材质，这些是后续工作。

训练支持 `--initialize`：只迁移兼容权重，重新建立优化器和步数，并记录父权重 SHA256；它与严格断点续训 `--resume` 互斥。只允许同结构迁移或 spatial → dual 扩展，校验文本编码器身份、尺寸和输出契约，不接受任意漏键加载。

`train.trainable: attributes` 冻结所有继承权重，仅训练新属性编码器、注意力和门。阶段二使用此模式；因此无参考的文字输出应逐像素保持不变，评估会实际检查这一点。

## 本次开发试验

脚本：`scripts/run_attribute_pilot.py`；产物：`outputs/attribute_prior_20261102/`。

1. 保留原目录的项目划分，从训练集取全部 6188 个配对目标，加 8000 个非配对物品，共 14188 个目标。新增目标优先覆盖 14 个描述关键词类别，每类最多先取 500 个，余量随机补齐。这是弱标签采样，不是人工审核过的形状族标注。
2. 从上一轮第 3000 步配对权重开始，在扩展数据上继续纯文字训练 1600 步，batch 64，学习率 5e-5。不是重新从随机权重训练，也不是对全量数十万目标充分训练。
3. 从阶段一最佳验证 flow 权重扩展 dual 模型，冻结底座，训练属性适配器 1000 步，batch 64，学习率 3e-4。任务比例为联合条件 85%、纯参考 15%。
4. 两阶段均按固定验证 flow 选权重。训练验证集共 384 个目标；生成开发集另取 96 个配对目标和 96 个非配对目标，与本次训练验证目标不重叠。仍来自既有 val 项目，不声称全新盲测。
5. 比较旧基线、扩展文字底座、属性适配器；固定噪声、40 步 Heun、条件强度 2。检查旋转参考、打乱参考、保留参考形状模式、纯参考入口；另复用既有 48 条语义探针作为开发诊断。

原锁定测试集不用于本次挑选权重或调参。无空间属性路径的旋转不变性是结构性质，不单独作为质量成功证据：还必须检查属性参考是否改善颜色、打乱参考是否产生合理影响、类别是否可辨认。像素重建误差可能惩罚合理形状变体，不能替代 MC 风格人工评分。

## 运行

使用本机 mcgen 环境并设置 `PYTHONPATH=src`、`HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1`。四个阶段依次执行：

```bash
python scripts/run_attribute_pilot.py prepare
python scripts/run_attribute_pilot.py text --device cuda:1
python scripts/run_attribute_pilot.py adapter --device cuda:1
python scripts/run_attribute_pilot.py evaluate --device cuda:1
```

脚本使用固定实验路径，已有数据/训练/评估目录会拒绝覆盖。若重做实验，应先改成新的独立实验目录并重新冻结协议。常规续训可通过 `mcgen train --resume` 使用完全一致的配置与 catalog。

生成 dual 检查点时：

```bash
mcgen sample --checkpoint outputs/attribute_prior_20261102/adapter/best_flow.pt \
  --prompt 'blue gemstone' --reference reference.png --reference-mode attributes \
  --out outputs/blue_gem_attributes.png --device cuda:1
```

把 `--reference-mode` 改为 `shape` 可允许参考轮廓参与；API 对应字段为 `reference_mode`。

## 本轮结果（已完成）

阶段一完成 1600 步，按验证误差选中第 800 步；阶段二完成 1000 步，选中第 400 步。两者都是阶段内步数。选中属性模型的 178 个继承张量与其父底座逐位相同，192 个开发目标的纯文本输出也逐像素相同。

生成检查覆盖 96 个配对目标（73 个项目）、96 个非配对目标（69 个项目），共 1440 条条件对照记录；另生成三组模型各 48 张语义探针，共 144 张。记录、图片路径、开发集/配置哈希及三个检查点哈希均已核验。

按项目平均的指标如下，MAE 为 0–255 的黑白背景合成误差，越低越好；IoU 越高越好。

| 开发集/模式 | MAE | alpha IoU |
| --- | ---: | ---: |
| 配对：旧模型，仅文字 | 38.45 | 0.694 |
| 配对：扩展底座，仅文字 | 36.43 | 0.709 |
| 配对：新属性模式，正确参考 | 36.02 | 0.717 |
| 配对：新属性模式，打乱参考 | 36.06 | 0.716 |
| 配对：旧空间参考模式 | 22.64 | 0.899 |
| 配对：新模型显式 shape 模式 | 21.15 | 0.922 |
| 非配对：旧模型，仅文字 | 48.66 | 0.489 |
| 非配对：扩展底座，仅文字 | 48.44 | 0.534 |

扩展底座在非配对开发集上的 IoU 增益为 0.0448，项目配对 bootstrap 95% 区间 [0.0238, 0.0660]；MAE 改善仅 0.215，区间 [-1.828, 2.089]。这支持轮廓覆盖的局部改善，不支持整体重建或语义质量已经大幅改善。固定语义图中苹果、花和宝石的轮廓更完整，钥匙仍断裂，书仍经常呈圆形。这些是助手目视观察，不是人工盲评通过率。

**参考轮廓干扰确实被隔离，但外观控制尚未成功。** 96 个配对案例的参考旋转 90° 后，属性模式的输出全部逐像素相同；旧模型输出平均 RGBA 改变量为 43.50，新模型显式 shape 模式为 45.46。这首先验证了设计上的排列不变性，不代表 MC 风格合格。

正确参考相对打乱参考，属性模式的 MAE 收益只有 0.035，95% 区间 [-0.048, 0.158]；palette MAE 收益为 -0.033，区间 [-0.161, 0.086]。二者均未显示可靠优势。正确/错误参考间的输出合成差异平均仅 0.629；启用属性路径相对完全不用参考的差异却有 5.340。这提示新分支很大一部分作用是普遍修正输出，而不是利用当前参考的具体外观，不能把“不随旋转变化”包装成属性迁移成功。

palette 指标为单向最近颜色距离，空前景时不可用；配对置信区间只使用两侧都有效的样例，因此不一定等于各组独立均值之差。所有置信区间只反映本次开发项目的变动，不涵盖训练随机种子或全体 Minecraft 资产。

本轮不提升该模型为默认模型。纯参考入口和显式 shape 模式仍可使用空间路径，但它们仍会跟随参考几何，不能宣称已解决用户提出的风格分布问题。

## 下一轮应改变什么

目前已有文字描述常常包含颜色/材质，配对重建并不强制模型从参考中读取这些信息；同时，选中的属性阶段只有 400 步，且底座完全冻结。监督不足、训练量和冻结约束都是候选原因，尚未被单因素消融隔离。

下一轮应优先增加“固定类别和形状、只改变外观”的明确监督：对目标与参考同步改色、保持目标 alpha/轮廓不变；联合训练时给类别/形状文字而隐藏颜色词，并审核此类描述的正确性。以参考换色是否引起正确换色、形状是否稳定作为独立验收。还需人工审核一批 MC 常见形状族锚点，解决书、钥匙等类别本身生成错误的问题。不要只增加同一配方的训练步数，也不要仅凭无空间分支的结构不变性认定目标达成。

## 工程验证

新增测试覆盖属性排列不变性及颜色敏感性、空间路径保留、历史配置兼容、零门迁移的输出一致性、冻结底座、断点续训和默认推理路由。相关回归测试 42 项通过，有两条上游 API 测试弃用警告。随后收紧空 reference_mode 值处理，新增三项测试再次通过。实验产物保留原始权重和逐样本记录，没有覆盖上一轮模型或已锁定测试。
