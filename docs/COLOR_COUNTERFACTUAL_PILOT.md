# 第二轮：固定类别与形状的参考换色监督

接续 [第一轮属性分支试验](ATTRIBUTE_PRIOR_PILOT.md)。上一轮隔离了参考位置结构，但正确参考相对打乱参考没有可靠收益。本轮改变训练数据，让同一类别、同一形状对应多种颜色，文字不能泄漏所需颜色；仍沿用 Qwen3-8B，冻结原有底座，只训练属性编码器、属性注意力和门。

## 数据审查与范围

预览暴露出原关键词标签的问题：苹果派被归入苹果、花盆归入花、含 emerald 材质词的锄头归入宝石、potion cake 归入药水。新增 `category_from_caption` 优先识别明确物品名，并排除复合物品；不再用 emerald/diamond 等材质词直接认定宝石类别。

保守规则仍不能替代人工标注。第二次预览仍有低支持度小类歧义，因此本次只训练有开发集覆盖的八类：镐、剑、斧、铲、头盔、宝石、门、锭。书、钥匙、花、苹果等不属于本轮成功范围，也没有补齐原版形状族标注。

最终产物目录为 `outputs/color_counterfactual_focused_20261102/`。较早的 `color_counterfactual_20261102/` 和 `color_counterfactual_v2_20261102/` 只保留数据审计记录，均未训练。

- 训练：1059 个原始物品，每个 6 个色相变体，共 6354 个目标。
- 固定验证：57 个物品、342 个变体；训练期间每次按固定规则选 256 个目标。
- 生成开发集：26 个物品、156 个变体，两个固定生成种子。
- 保留原始 train/val 项目划分，不读取 test 作为开发样本。增强后检查跨集合目标哈希碰撞，并检查开发变体是否等于父模型已见过的原目标；本次未发现需隔离的碰撞。不能排除感知近重复。
- 原配对需有足够可见彩色像素、集中主色，目标和参考的主色色相差不超过 30°。不猜测前景分割，白色与灰色背景在主色统计中没有色度权重。

## 变换与训练

`src/mcgen/color_supervision.py` 对目标和参考应用同一 HSV 色相旋转。alpha、像素位置、RGB 最大/最小值以及原生像素网格保持不变；这保持 HSV 明暗层次，不等于感知亮度严格不变。中性色不被染色。整个物品同步改色，可能包括工具柄，因此它是可控颜色诊断，不是材料区域编辑或真实材质变化。

训练和固定验证使用 0/60/120/180/240/300°；生成开发集使用 30/90/150/210/270/330°。后者是未用于训练的变换角度，不代表绝对颜色从未出现过。文字统一为类别描述，不含颜色或材质词；没有给原参考和原目标使用不同的色相变换。

从上一轮属性模型第 400 步权重初始化，使用新的优化器，训练 2000 步、batch 64、学习率 3e-4，仅联合条件。严格按固定验证的最低 `joint_flow_mse` 选择检查点，生成开发结果不参与选权重。架构及原有底座保持不变；数据筛选、描述方式和训练量同时改变，不能把结果归因于单一因素。

脚本和配置：`scripts/run_color_counterfactual.py`、`configs/v3/experiments/color_counterfactual.yaml`。

```bash
# 使用 mcgen 环境，设置 PYTHONPATH=src 与离线 HF 环境变量。
python scripts/run_color_counterfactual.py prepare
python scripts/run_color_counterfactual.py train --device cuda:1
python scripts/run_color_counterfactual.py evaluate --device cuda:1
```

已有实验路径会拒绝覆盖；重新做试验须使用新目录并冻结新协议。18 项相关测试通过，包括复合物品排除、材质词不充当类别、改色不改变 alpha/网格、改色逆变换误差及原属性分支兼容性。

## 评估规则

对上一轮模型和本轮选中模型，使用同一文字、同一噪声，分别生成无参考、正确参考、错误颜色参考、旋转参考。错误参考来自**同一物品**的另一色相版本（相差 120°），保持形状与内容身份不变，从而避免把换物品的影响误当作换色控制。

主色误差使用圆周距离。输出没有足够彩色像素或主色过于分散时，按 180° 失败计入，不能通过生成灰白图规避误差。色相误差不超过 30° 的比例只是颜色指标，不是 Minecraft 风格或语义合格率。报告同时检查目标 alpha IoU、跨颜色输出的 alpha IoU、旋转敏感性和纯文字输出一致性。

另对上一轮固定开发集的前 24 个原始配对物品，回测纯参考入口和显式 shape 模式。这是回归诊断，不用于本轮选权重。所有结果仍是开发集实验、一个训练种子；缺少独立人工盲评和真实照片材质测试。

## 完成结果

训练完成 2000 步，最低联合验证 flow MSE 出现在第 2000 步，为 0.08743；同批固定验证的纯文字误差始终为 0.10815。178 个继承的底座张量逐位相同，生成评估中的纯文字输出也逐像素保持一致。

生成评估包含 26 个物品、21 个项目、156 个变体、两个种子。新旧模型与四种条件共 **2496 条**记录，另有 **96 条**原入口回归记录；所有记录对应图片、数据 catalog、开发清单、配置和检查点哈希均已核验。

以下为开发集按项目平均的正确参考结果：

| 指标 | 上一轮属性模型 | 本轮同步改色模型 |
| --- | ---: | ---: |
| 主色色相误差 ≤30° 比例 | 15.61% | 74.01% |
| 主色平均误差（含无效输出的失败惩罚） | 95.73° | 25.74° |
| 合成 MAE（0–255，低为好） | 33.45 | 24.63 |
| 目标 alpha IoU | 0.826 | 0.841 |

色相误差降低 69.99°，项目配对 bootstrap 95% 区间 [59.92°, 79.91°]；颜色达标比例提高 58.40 个百分点，区间 [47.35, 68.85]。这些区间反映本次开发项目差异，不覆盖训练随机种子的不确定性。目标 IoU 增益的区间包含零，不能宣称目标形状质量显著提高。

当提供同物品的另一颜色参考时，新模型相对原目标的色相误差升至 116.25°，相对实际提供的颜色则仍为 25.74°。上一轮相对实际提供颜色的误差为 95.73°。结合图片可确认：本轮不再只是对所有输入做同样的输出修正，参考颜色已经能控制生成颜色。

**轮廓基本稳定，但不是完全解耦。** 同一物品在不同参考颜色下的输出 alpha IoU 平均为 0.9834，上一轮为 0.9999。颜色控制增强后仍有小幅形状变化。宝石的目标形状 IoU 按案例平均从 0.705 降到 0.687；全局颜色改善不能掩盖这一类的形状问题。

固定顺序预览显示，镐、剑和宝石可以随参考换色；同时仍有偏白、过饱和、局部颜色分配不准确和形状不匹配。头盔颜色指标较好，但只有两个源案例，不能外推为该类别普遍合格。助手目视检查不是独立人工盲评。

## 旋转数值审计

原始报告中的 `rotation_max_absolute_pixel_change=255` 不能直接解释成几何泄漏。进一步检查了全部 312 组新模型旋转对照：

- 308 组整图逐像素相同；312 组的 alpha ≥128 二值轮廓均相同。
- 黑白背景可见差异的保守平均为 0.00335/255，最大单通道差异约 3.97/255；alpha 最大差异为 3/255。
- 原始 RGB 差异 255 的两个案例发生在 alpha 从 0 变成 1 的边缘像素：完全透明时 RGB 被规范化为零，极低 alpha 时可保留蓝通道 255，实际可见差异很小。
- 对这两个案例单独检查，预处理后的参考严格互为旋转，禁用的空间 token 完全相同；属性统计 token 的最大差异为 4.77e-7。结果符合浮点归约与后续量化敏感性，而非参考朝向被空间路径传入。不能声称所有输出严格位级旋转不变。

原始指标保留未改，详见 `rotation_precision_audit.json` 与 `rotation_context_audit.json`。

## 原入口回归与使用结论

对固定 24 个原始物品的样本平均：

| 模式 | 上一轮 MAE / IoU | 本轮 MAE / IoU |
| --- | --- | --- |
| 纯参考入口 | 21.87 / 0.912 | 24.98 / 0.891 |
| 显式 shape 模式 | 19.24 / 0.943 | 20.04 / 0.922 |

冻结底座并不保证参考入口不变，因为这些入口也调用可训练的属性分支。本轮只有联合属性条件训练，原入口发生退化。因此**不提升为默认模型**，保留为 opt-in 颜色控制实验权重：

`outputs/color_counterfactual_focused_20261102/train/best_joint_flow.pt`

使用时给出类别文字，并显式选择 `reference_mode="attributes"`；CLI 对应 `--reference-mode attributes`。不要把这一结果宣传为一般材质迁移、原版 Minecraft 风格认证，或所有类别生成问题已经解决。原模型和数据均保留。

下一轮应先隔离新属性学习对纯参考/保留形状入口的影响，并增加原入口回放或约束；同时建立经过核对的形状族和物品部件标注。数据审计表明，扩大旧关键词数据会继续引入类别错误，仅继续延长同一配方的训练不足以解决问题。颜色控制与形状质量应分别验收。
