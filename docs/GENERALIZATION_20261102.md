# 泛化验证与 MC 形状先验诊断（2026-11-02）

## 结论

当前模型学会了跨项目的配对参考图转换，但尚未证明能够稳定生成符合 Minecraft 常见形状分布的物品。用户指出的参考图依赖问题有直接的实验支持：固定文字和噪声，只旋转参考图，镐的输出轮廓也跟着旋转；增加“保持 MC 常见形状”的提示没有纠正。重建指标不能充当 MC 风格合格率。

本轮完成训练、锁定测试和补充诊断，没有修改生产模型架构或默认采样参数。下面的架构调整是后续设计，不是已经实现的能力。

## 协议与覆盖范围

所有产物位于 `outputs/generalization_v3_20261101/`。`protocol.json`、`locked_manifest.json`、`checkpoint_selection.json` 记录预设协议、样本与权重身份。

- 冻结本地 Qwen3-8B，文本投影前 LayerNorm；原生 16×16，宽度 256、8 层，文本/参考图独立交叉注意力。
- 从头训练 6000 步，batch 64，训练池为 1795 个项目的 6188 个配对物品目标。它不是整个 MC 数据库的全量训练。
- 按预先约定的验证集三任务平均 flow MSE 选择第 **3000 步**，不是按测试图挑选，也不是评估第 6000 步。3000 步后的验证损失出现退化。
- 选中权重实际见过全部 6188 个目标；计入 joint 后，平均每目标文字条件出现 21.69 次，参考条件出现 13.99 次。
- 锁定配对测试 512 个目标、188 个项目；另有非配对目标的文字测试 256 个目标、132 个项目。训练/验证对照各 128 个目标。
- 测试使用两个生成种子，40 步 Heun；文本和参考强度均为 2。训练/验证对照使用一个种子。生成 batch 在测试推理前从 16 改为 128，仅为计算效率，另记 `evaluation_addendum.json`。
- 锁定样本、配置和选中权重的 SHA256 已复核。人工盲评分表已生成，但未填写；不报告虚构的人类合格率。

## 定量结果

以下是按项目平均的黑白背景合成 MAE（0–255，低为好）及 alpha IoU（高为好），区间为项目 bootstrap 95%。多个生成种子不当作独立项目。

| 条件 | 配对测试 MAE | 配对测试 alpha IoU |
| --- | --- | --- |
| 仅文字 | 40.97 [38.12, 43.68] | 0.642 [0.612, 0.673] |
| 仅参考图 | 28.40 [26.29, 30.60] | 0.821 [0.799, 0.842] |
| 文字＋参考图 | 26.80 [24.49, 29.20] | 0.832 [0.809, 0.852] |

非配对目标的文字测试 MAE 为 50.52 [46.47, 54.42]，alpha IoU 为 0.537 [0.495, 0.580]。这套测试分布不同，不能把与配对集的差值解释成单一因素的因果效应，但说明现有结果不足以支持广泛物品生成能力。

正确文字相对打乱文字使 MAE 降低 25.64 [22.61, 28.80]；联合条件中正确参考图相对打乱参考图降低 27.88 [25.81, 30.15]。模型确实使用了两种条件，但“条件有效”不等于“遇到冲突时按 MC 形状先验处理”。

使用相同第一种子比较测试和训练，文字 MAE 增加 8.85 [4.47, 13.32]，联合 MAE 增加 5.50 [2.00, 9.09]。不同项目组成也会影响差异，不能单凭此判定过拟合原因。

训练目标最近邻扫描未发现生成结果在编码空间 MSE < 1e-6 的直接复制。配对测试真值中仍有 47/512 个与训练目标 MSE < 0.005，可能存在相似变体；精确去重和项目划分不能排除全部近重复或未知素材血缘，也不能证明没有记忆。

完整指标、条件打乱实验、置信区间见 `results_summary.json`；逐样本记录见各 `eval_*/samples.jsonl`。带目标 alpha 的缩放基线是使用真值的诊断上界参照，不能作为可部署基线。

## 参考图形状控制实验

这是在锁定测试之后，根据用户反馈追加的探索性验证。取锁定验证集顺序中的两把镐、两颗宝石；固定每例噪声和原始文字，只改变参考图朝向，另测试明确 MC 形状提示和参考强度 0.5。未据此重新选择权重或调整正式测试。

| 样例 | 原参考联合输出与原目标 IoU | 旋转 90° 后与原目标 IoU | 旋转后与旋转目标 IoU |
| --- | --- | --- | --- |
| 青铜镐 | 1.000 | 0.171 | 1.000 |
| 铅镐 | 0.919 | 0.254 | 0.756 |
| 品红宝石 | 0.912 | 0.707 | 0.846 |

明确要求保持 MC 形状时，青铜镐与旋转目标 IoU 仍为 0.986，铅镐为 0.848。降低参考强度后，两把镐与原目标 IoU 回到 0.821 / 0.942；但圆形银色宝石从原参考联合输出的 1.000 降到弱参考条件的 0.592，说明简单削弱参考会损失有用信息。

第四个宝石的目标 alpha 旋转对称，无法用 alpha 判断朝向，不能计入方向判断。这里所谓“原目标”只是已有 MC 素材，不是官方原版模板；这四例足以展示失败机制，不能估计所有物品的发生率。旋转测试也不等价于真实照片的分布外测试。`joint_rot180` 行的 `rotated_target_iou` 仍是相对 90° 目标计算，不能作为 180° 跟随程度；本结论只用 90° 对照。

## 定性观察（助手检查，非人工盲评分）

固定顺序的配对测试预览第 000、032 页显示，参考图通常改善轮廓，但仍有颜色偏移、透明边缘异常和细节简化。非配对文字测试第 000、016 页有明显类别/轮廓不匹配。另完成 12 类 × 4 颜色 × 2 种子的 96 张预设文字探针：首个种子的镐和部分剑可辨认，钥匙、宝石、书等仍有明显形状失败，改变颜色也可能改变对象结构。它不是已证明未见过的组合测试。

因此，本轮可以确认配对条件迁移有所建立，不能宣布通用文生 MC 物品或原版风格生成已经合格。

## 设计原因与下一阶段方案

现有 `src/mcgen/model.py` 把参考图编码为带位置的 16×16 空间 token；虽然文本和图像注意力已经分开，参考分支仍可直接控制几何。分支分离不等于颜色、材质、形状解耦。训练又从配对子集直接联合开始，目标是复现配对像素，未提供“同属性、不同参考形状，仍输出 MC 常见轮廓”的监督。这种目标与结构组合可以通过跟随参考几何完成任务。它是与观察一致的解释，尚未通过架构消融隔离各因素贡献。

建议默认产品语义为：**类别和 MC 形状族决定轮廓、朝向与比例；参考图提供颜色、材质、局部装饰。** 允许用户明确选择保留参考形状，以容纳自定义物品和特例。宝石、镐都应有多个合理形状族，不能硬编码成每类一个模板。

实施顺序：

1. **先建立 MC 物品先验。** 整理原版锚点与可信模组物品，补充类别、形状族、朝向、风格来源和例外标记；审核已有描述中的类别噪声。在更广的去重 MC 物品集上训练文本生成底座，按类别/形状族平衡采样，先验证无参考时的可辨认度。保留 Qwen3-8B；更换文本模型不是本次证据指向的优先项。
2. **再接入受限的参考属性分支。** 比较池化属性 token 与当前空间 token 的消融；默认属性路径尽量弱化位置和轮廓信息。另设显式启用的形状分支，独立控制形状保留程度。池化本身不保证解耦，必须通过冲突实验验证；避免只有参数名称分开、实际作用仍混合。
3. **训练时制造正确的冲突监督。** 对同目标使用形状/朝向不同但颜色材质一致的参考；属性模式保持目标几何，形状模式才要求跟随参考。对无法可靠迁移属性的变换进行筛选。先冻结或小幅更新底座，再比较分阶段解冻，防止参考适配破坏文本先验。
4. **保留两种入口。** 文本入口可直接给类别和形状族；纯参考入口须先推断类别/形状族，再由底座生成，不能假设文本版 Qwen3-8B 能直接看图。可训练独立视觉类别头，对类别模糊的输入允许用户指定类别。
5. **重做验收标准。** 分开考察类别可辨认度、MC 形状族符合度、颜色材质保持、参考几何干扰、像素簇/边缘质量；同时测试默认 MC 模式和保留参考形状模式。预先锁定跨项目、跨形状族、真实照片/插画参考的留出集，并由人盲评；重建 MAE 只作为其中一项辅助指标。

下一轮应先做“广泛文本底座 → 受限参考适配”的小规模消融，再扩大训练。当前权重和本轮锁定测试保留作基线，新增方案需要新的开发集和最终留出集，避免反复针对已看过的测试调参。
