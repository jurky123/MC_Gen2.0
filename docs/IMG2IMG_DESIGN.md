# MC-Gen 2.0 图生图 / HD→MC 风格化：设计文档（草案 v0.1）

> 状态：**设计阶段，暂不实现**。请在此基础上细化与决策。
> 关联：`mc_texture_generation_complete_plan_v2.md`（文生图主线）、`PROGRESS.md`。

---

## 1. 背景与动机

### 1.1 现状
- 主线是 32×32 RGBA 的**像素空间 Rectified Flow Transformer**（MC-FlowDiT），条件为文本（冻结 Qwen3-8B token 序列 + cross-attention）。
- 已完成 Stage 1（像素风预训练）→ Stage 2（全量 MC + grounded prompt）→ Stage 3（2 万条 27B 精标子集 + replay 微调，frozen 变体无遗忘）。
- 现有 t2i 能力：颜色稳定（命中 ~0.7–0.8）、常用概念可对上（概念召回 ~0.3–0.5）、block/item 基本可辨；**细节与罕见语义弱**。

### 1.2 观察到的两个瓶颈
1. **标注数据不够好**：27B 精标仍会漏细节、误判（例：红裤子护甲被标成 "molten / green"；头盔细节缺失；宝石/锭的局部结构未描述）。
2. **拟合还不够**：小模型 + 小精标集，长尾细节欠拟合。
3. 共同点：**纯文本条件无法承载高频细节**，数据侧也很难把细节标注得又全又准。

### 1.3 转向思路
引入**图像条件（图生图）模态**：给一张高分辨率游戏素材/参考图，生成对应的 MC 风格低分辨率纹理。这样：
- 结构信息由**参考图**直接提供，不再依赖标注把细节写全；
- 可借用外部**高清生图模型**的能力（高清素材生成/超分/重绘）来制造配对数据；
- 得到的图生图能力又能**合成更多高质量像素数据**，反哺文生图（数据飞轮）。

---

## 2. 目标与非目标

**目标（首版）**
- 给定 (参考图, 可选文本) → 输出 32×32 RGBA MC 风格纹理；参考图提供结构与细节。
- 支持 16×16 native 与 64×64 的后续扩展接口。
- 用图生图合成数据，**可量化地提升** t2i 的细节/语义指标。
- 不牺牲现有 t2i 能力（防遗忘）。

**非目标（首版）**
- 任意自然照片→MC 的通用风格迁移；
- 像素级重建原参考图（不是超分/复原）；
- 一上来就做 64×64 主训练。

---

## 3. 总体架构：双向"高清↔MC"飞轮

```text
                 (1) 文生图 t2i  ──────────────►  32×32 MC 纹理
                        ▲                                 │
                        │ (5) 用增强数据重训               │ (2) HD-ify
                        │                                 ▼
                 (4) 过滤/去重/评估  ◄──  (3) HD→MC 风格化  ◄── 未配对/配对
                        ▲                     (img2img 模型)      HD 素材
                        │                                 ▲
                        └─────────────────────────────────┘
                              (0) 高清素材来源（自生成/CC0）
```

两条造配对数据的路径：
- **Path A「HD-ify」(MC→HD)**：拿现有 32×32 MC 纹理当低分辨率 init/参考，用**外部高清 img2img 模型**（FLUX / SDXL + ControlNet）在文本 prompt 引导下重绘出"高清版本"。得到配对 `(HD, MC)`，MC 侧正是目标域。
- **Path B「MC-ify」(HD→MC)**：对高清图做**确定性像素化**（nearest 下采样到 16/32 + 调色板量化 k 色，可选 ordered dithering）得到 MC 侧。零模型、可无限扩展。
- **Path C「学习式风格化」**：训练我们的 HD→MC 图生图模型，替代/增强 Path B。

推荐：**先用 Path B 建立大规模配对底料（无限、干净、可控），用 Path A 补充"看起来像真实 res-pack 重绘"的样本；再训练 Path C（图生图模型）；最后用 C 反哺 t2i。**

## 4. 数据策略

### 4.1 高清素材来源（**license 必须干净**）
> 版权提醒：不要直接抓取商业游戏的高清素材（与 README 去除数据集内容的初衷一致）。候选：
1. **自生成**：用有明确许可的高清生图模型（如 FLUX / SDXL 系列）按 caption 生成"高清游戏素材风格"图片；版权风险最低、可控性最好。
2. **CC0 / CC-BY 素材包**：程序化材质、OpenGameArt 等（需逐项审计）。
3. 已删除的 MatSynth/ambientCG **不重新引入**（与 v2.3 路线一致），避免回到旧路线；如要用，需单列审计与许可。

### 4.2 配对构建
- `Path B`：HD → nearest 下采样到 16/32 → k-means/median-cut 调色板量化（k∈{8,16,32,64}）→ 可选抖动。产出 `(HD, MC32)`。
- `Path A`：MC32 → 外部 img2img（低强度 denoise + ControlNet/深度/边缘约束）→ HD → （可再 Path B 回落到 MC 侧以确保配对一致性）。产出 `(HD, MC32)`。
- 统一配对存储：`pairs/{split}/` 或 mmap `hd.uint8.mmap (N,64,64,3)` + `mc.uint8.mmap (N,32,32,4)` + metadata。
- 清洗：内容 SHA 去重、近重复（pHash）、按来源/license 分桶、极低信息图剔除。

### 4.3 Split
- 按**素材来源/项目**切分，禁止同源跨 split（沿用 project_id split 原则）。
- 评估集固定一批"人工挑选的困难样本"（细节丰富、长尾材质、对称/发光/透明）。

## 5. 模型设计

### 5.1 条件注入方式（候选）
1. **参考图通道拼接（最简单、pixel-space 友好）**：把参考图（HD 下采样到 32，或 32 的 RGB）与噪声目标在通道维拼接，`in_channels = 4(目标) + 3/4(参考)`；参考通道固定不变，模型学"去噪时对齐参考"。
2. **参考 token 交叉注意力**：参考图经小卷积/patch embed → token 序列，作为 cross-attention 的 K/V（与文本 cross-attn 并列或合并）。
3. **二者结合**：通道拼接给结构，cross-attn 给可控融合。
4. **ControlNet 式**：在主干旁挂条件分支（参数多、训练重，首版不建议）。

建议首版：**方案 1（通道拼接）+ 方案 2 可选**，与现有 `cross_attention` 文本通路并存。

### 5.2 与现有模型的关系
- **选项 X（推荐首版）：独立"风格化器"**，结构沿用 MC-FlowDiT，新增参考条件；**t2i 主干不动**，彻底避免遗忘。
- **选项 Y：统一模型**，参考条件 dropout（如 10–20%）→ 同一模型同时支持 t2i（丢参考）与 i2i（给参考）。优雅但有遗忘风险，需 replay/低 LR。
- 建议先 X，验证后再考虑 Y（把参考分支合并进来）。

### 5.3 条件配置
- 双 CFG：文本与参考图分别可 drop，推理时两个 guidance 权重可调。
- 参考图分辨率：首版 32/64；HD-ify 时外部模型用 512/1024，但送进我们模型前降采样。

### 5.4 目标与损失
- 条件 Flow Matching：`x0` = MC 目标；条件 = (参考图, 文本)；同现有 `flow.py` 约定。
- 可选：边缘/tile loss（沿用）、参考一致性 loss（如输出与参考在低频/边缘上的一致性，权重小）。
- 首版保持 MSE + uniform t。

## 6. 训练方案（含防遗忘）

- 数据：`(HD, MC)` 配对；文本来自现有 grounded/精标 prompt（可选，参考图已给结构）。
- 冻结/低 LR：若沿用选项 X，仅训练新参考分支；若选项 Y，复用 Stage-3 的 replay + 低 LR + 可选 `freeze_backbone`。
- batch/显存：参考通道使输入增大，micro_batch 需下调（沿用 auto_probe/手动）。
- EMA + 双 val 选点（i2i val + t2i 回归 val）。
- 关键：**任何对 t2i 主干或文本通路的更新，都必须跑 t2i 回归评测**（见 §8）。

---

## 7. 数据飞轮 / 自提升循环

1. t2i 采样一批纹理（多样 prompt + 多种子）。
2. 对每张做 `HD-ify`（Path A）→ 得到 HD 参考；再 `MC-ify` 回落或直接配对。
3. 用图生图模型对这些样本**重绘/精修**，或用 stylizer 直接生成新 MC 样本。
4. **质量过滤**：VLM 打分（概念/颜色/细节/是否崩坏）+ 去重 + 多样性（pHash）。
5. 通过过滤的样本**并入 Stage 2/3 数据**，重训 t2i（低 LR + replay）。
6. 回到 1，迭代。记录每轮的评测指标，防止退化。

> 注意闭环风险：自蒸馏会导致分布收窄。需**保留真实数据比例**、引入外部新素材（Path B 的 HD 源）、并做多样性约束。

---

## 8. 评测

### 8.1 图生图（配对）
- 保真：与目标 MC 的 RGB L2 / 调色板距离 / 唯一颜色数一致度；
- 结构保持：与参考图在多尺度边缘/梯度上的一致性；LPIPS（可选）；
- 可平铺性：seam（沿用 `src/eval/seam.py`）；
- 透明度/发光等属性保持（分类器或 VLM 判断）。

### 8.2 文生图回归（防遗忘）
- 沿用 `scripts/eval_generation.py`：concept recall、colour、real-vs-gen 保真、seam、diversity、retrieval、`text_effect`（固定种子）。
- 额外：与上一版 checkpoint 的**成对差异**，检测分布漂移。

### 8.3 下游增益
- 消融：t2i 训练集 **有/无** 图生图合成数据 → 对比概念召回/细节指标。
- 人工/VLM 小集盲评（细节、合理性、崩坏率）。

## 9. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 版权 | HD 素材来源 | 只用自生成/CC0；逐项审计；不抓商业素材 |
| 配对噪声 | Path A 重绘可能改变内容 | 用低 denoise + ControlNet；Path B 保底；VLM 过滤 |
| 闭环自蒸馏收窄 | 只用自产数据 | 保底真实数据比例、引入外部 HD 源、多样性约束 |
| 模式塌缩 | 生成趋于少数调色板/形状 | 多样性指标监控、prompt/参考增广 |
| 遗忘 | 改动主干/文本通路 | 独立模型优先；replay + 低 LR + 冻结 + 回归评测 |
| 算力 | 外部高清 img2img | 批量化、缓存 HD 结果；只对需要的子集重绘 |
| 评测可信度 | 细节难量化 | 人工 golden 小集 + VLM 裁判 + 定种子指标 |

## 10. 分阶段实施计划（暂不实现）

- **Phase 0 — 原型与配对底料**
  - 选外部 HD 生成器（先自生成 prompt 集）；实现 Path B 像素化；构建 1万级 `(HD, MC32)` 配对；人工抽查。
- **Phase 1 — 图生图模型（独立）**
  - 在 MC-FlowDiT 上加参考条件（通道拼接优先）；训练风格化器；配对评测。
- **Phase 2 — HD-ify 增强**
  - 用外部 img2img 做 MC→HD 重绘，扩充配对；加入 VLM 过滤。
- **Phase 3 — 飞轮与反哺**
  - 合成数据并入 Stage 2/3；重训 t2i（防遗忘）；消融验证"有/无合成数据"。
- **Phase 4 — 扩展**
  - 16×16 native、64×64、多面（top/side/bottom）一致生成、调色板条件生成。

## 11. 需要决策/细化的点（留给你）

1. **外部高清生图模型选型**：用哪个（FLUX.2 / SDXL 系列 / 其他）、在哪跑、许可与配额；是否允许云端 API。
2. **配对路线优先**：先做 Path B（确定性像素化，底料）还是先做 Path A（重绘）？
3. **模型形态**：独立风格化器（选项 X）还是统一模型（选项 Y）？
4. **参考条件实现**：通道拼接 / cross-attn / 两者结合；参考图分辨率（32 vs 64 vs 多尺度）。
5. **分辨率目标**：首版 32 还是直接上 16×16 native（pixel fidelity 更强）？
6. **闭环配比**：合成数据占比上限、真实数据保底比例、过滤阈值。
7. **评测与 golden 集**：人工挑选困难样本的清单与标注规范（与现有 caption bench 合并？）。
8. **与标注问题的关系**：是否用"HD 参考"来**辅助/校正标注**（例如用 HD 版本给 VLM 看细节以减少漏标）——这可能同时缓解 §1.2 的标注问题。
