# 文件文本监督

当前路线使用文件信息抽取文本，不使用视觉模型生成的描述。生成模型从零训练。当前新实验使用冻结的 **Qwen3-VL-Embedding-8B** 官方最终归一化向量作为文本条件，替代此前的通用 Qwen3-8B 中间层特征。

抽取保留太阳、灵魂、材料等名称；规范化驼峰和分隔符，移除明确的动画帧编号。根据已恢复的资源路径、组件标识和图层后缀隔离异常样本。没有恢复原路径的名称仍属于弱监督，不能视为核实过的游戏物品名称。

当前数据：311,510 张训练图片、40,808 张验证图片，每图一条文本；额外隔离 13,411 张训练图片。图片与原数据划分保持一致。

[查看可下载的小样本](../examples/data_review/README.md)，包含原图、处理结果、来源和已知漏收例子。可独立运行检查，不需要下载完整数据集。

实现与实验入口：

- `src/mcgen/resource_text.py`：文本抽取和隔离规则。
- `scripts/build_resource_text_training.py`：构建纯文件文本数据。
- `scripts/run_resource_text_training.py`：精确文本缓存及历史续训实验。
- `scripts/run_resource_text_scratch.py`、`scripts/queue_resource_text_scratch.py`：旧小模型的从零训练与评估。
- `scripts/compare_resource_text_interim.py`：固定提示、种子的检查点对照。

完整训练脚本依赖本地完整数据与缓存布局；模型权重、全量数据、缓存和运行输出没有上传。`grounded_labels`、视觉标注及对应队列属于已放弃路线的历史实验代码。

早期小模型从零训练的第 2,000 步，在固定 1,024 张验证图片上误差为 0.1873；数值低于旧模型，但部分物品类别和颜色控制仍不稳定。当前 README 已更新为扩容模型第 4128 步的真实输出。

## 扩容实验

`outputs/qwen_vl_embedding_large_20261103` 使用纯文生图主干：512 宽、12 层，约 8,141 万参数；不计算空参考图支路。

真实图文样本的完整优化器步实测：batch 672 峰值分配显存 67.45 GiB，约 863 图/秒；704 占用更多显存而吞吐未提高，768 OOM。该吞吐是热身后的模型训练计算，不等同于含读数据、验证及保存的端到端速度。

预算为 7,211 步、有效 batch 672、90% 文本条件，平均每图约 14 次文本条件曝光。预热 232 步，每 516 步验证；每次验证还检查高噪声下真实／打乱／空文本的差异，并保存固定提示的生成图。随机抽样的平均曝光不保证每张图恰好被采到 14 次。

新 Embedding 在测试文本上与官方实现逐值一致；缓存为每条文本一个 4096 维向量，不是通用语言模型的多层 token 特征。旧检查点继续使用其原编码器，不能混用缓存。

相关入口：`download_qwen_vl_embedding.py`、`prepare_embedding_large.py`、`queue_embedding_large.py`。验证官方预处理还需要 `pip install -e '.[embedding]'`。完整队列依赖本地完整数据布局，依次执行模型验证、Embedding 缓存、batch 实测、短测和正式训练。

该轮已完成 7,211 步，后期出现明显退化。用户比较生成结果后选用 **4128 步**；自动最小 Flow MSE 对应 4644 步，原始记录保持不变。当前不继续训练，参见[检查点对照](EMBEDDING_TEXT_20261103.md)。
