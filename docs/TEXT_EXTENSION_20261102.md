# 扩大数据集的 22,000 步续训与速度检查

用户要求继续学习、增加训练步数，并简要检查速度优化。沿用 `text_expansion2k_20261102` 的 2,055 张训练图与 216 张验证图；图像、文本、划分和采样比例均保持不变。详细描述异常时仅保留文件名监督，双文本图片内部等概率选择，图片目标均匀采样。

## 第一条试验方案（已停止）

- 从扩大实验第 6,000 步的 `training/latest.pt` 接续，累计至第 22,000 步，新增 16,000 步。
- 保留模型及 Adam 优化器状态；加载后核对优化器 step 为 6,000，不重新初始化动量。
- 保留全局 step 与原 seed，继续原来的按步确定的图片抽样、噪声与时间采样序列。
- 新学习率阶段从全局第 6,000 步开始：200 步预热至 3e-5，再在本阶段缓慢余弦衰减至约 3e-6。此前 6,000 步仍是原来较短的衰减计划，不能称为从头执行统一 22,000 步计划。
- 每 1,000 步验证和保存。固定终点后重跑原 227 个案例的前后比较，不修改原实验输出。
- 累计每图文本曝光约 154 次，接近此前 378 张核心实验的 152 次。

运行入口：`scripts/run_text_extension.py`。产物目录：`outputs/text_expansion22k_20261102/`。训练日志在 `outputs/text_expansion22k_20261102.training.log`。

新增 `train.schedule_start`（默认 0）支持全局采样步数与学习率阶段起点分开；旧配置默认行为不变。普通 `resume` 仍要求配置与目录指纹完全一致，本次新的学习率计划由专用续训入口显式加载优化器，并记录来源哈希与状态保持方式。

## 简要速度优化

原文本编码始终保留 128 个 token。优化仅在冻结 Qwen 编码之后、缓存输出拼接与 CPU→GPU 搬运之前，截掉批内最后一个有效 token 之后的遮罩位置；没有改 Qwen 的输入长度、有效 token 值或训练标签，也没有缓存可训练的投影。CPU 原始特征缓存仍保留 128 长度。

真实 batch 16 的两个交错测量轮次（每轮 30 次前向＋反向，先预热）中：

| 项目 | 原流程 | 截掉尾部 padding |
|---|---:|---:|
| 实际特征长度 | 128 | 50 |
| 第 1 轮每次耗时 | 83.96 ms | 69.46 ms |
| 第 2 轮每次耗时 | 88.69 ms | 71.12 ms |
| 平均每次耗时 | 86.33 ms | 70.29 ms |

该阶段吞吐约 1.23 倍，耗时降低约 18.6%。测量不包含初次 Qwen 编码、优化器更新、数据读取、验证及存盘；共享 GPU 的负载也会变化，不能宣称端到端同幅度提速。

有效特征与遮罩逐项相同；FP32 模型输出与梯度等价检查通过。BF16 真实批次 loss 差约 0.000957，说明内核形状变化会产生数值差异，不能承诺逐位复现。预先设置的启用门槛是吞吐提升超过 3%、loss 差小于 0.001，本次满足门槛并启用。原训练和推理入口默认关闭，专用续训入口选择开启；这一执行选择记录在 `speed_probe.json` 和 `training/run.json`。如手动恢复本轮检查点，应按该记录设置 `trainer.encoder.trim_padding`，以维持本轮执行方式。

相关测试：续训、精确 resume、模型/运行时集成和文本归一化共 11 项通过；随后新增非零模型参数下的 padding 输出与梯度检查通过（12 项不同测试）。沙箱内 API 集成测试停滞后已终止该测试进程，并在可正常执行的环境重跑通过。

## 更新：退化排查与主续训调整

第一条方案在第 17,303 步主动停止，最近的完整保存点为第 17,000 步。训练和验证误差持续上升，不能把更多更新当作学习改善，也不应把不合适的学习率重启当作“增加步数无效”的证据。

为检查 padding 优化是否引入问题，另在 GPU 0 从相同的第 6,000 步模型和 Adam 状态、相同全局随机序列出发，各训练 500 步，完整 padding 与裁剪 padding 共用冻结特征缓存：

| 500 步对照 | 完整 padding | 裁剪 padding |
|---|---:|---:|
| 平均训练 loss | 0.17350 | 0.15881 |
| 终点固定验证 loss | 0.17893 | 0.18538 |

两组验证误差均高于原终点 0.16423。逐步 loss 差的绝对均值为 0.01808；单批 FP32 等价和 BF16 小误差不足以保证长程更新轨迹接近。因此 padding 优化保持可选实验功能，**主续训关闭**。完整 padding 也退化，故不能单独把退化归因于裁剪；学习率等因素还未独立归因。

现在主续训使用 `outputs/text_expansion22k_conservative_20261102/`：从原始第 6,000 步权重恢复模型与 Adam，保留全局抽样步数，采用完整 128 长度特征；学习率从原末尾 5e-6 连续开始，在额外 16,000 步中余弦衰减至约 5e-7，不做学习率升高或预热。目标仍为累计 22,000 步。数据和异常描述回退规则保持不变。

运行入口为 `scripts/continue_text_conservative.py`，支持显式 `--resume`；日志为 `outputs/text_expansion22k_conservative_20261102.log`。`scripts/finish_conservative_extension.py` 已排队在训练完成后运行原 227 案例评估，以及相同的 157 条训练拟合探针。不会在主训练占用显存时并发加载另一个评估模型。

第一条试验的配置、检查点、速度测量及数值对照均保留在原 `text_expansion22k_20261102` 目录。主续训及三方对照现已完成；结果未取得整体泛化改善，不替换原恢复候选。


## 用户新增的最终点 / 最低误差点比较

长训结束后，对比原 6,000 步、保守续训期间最低固定验证 `text_flow_mse` 的检查点和最终 22,000 步。最优点来自训练日志与 `best_flow.pt`，不是看生成图后挑选；若最佳点就是终点，也如实记录为相同权重。

- 原 227 个固定案例分别评估，提示、种子和推理参数一致。
- 157 条固定拟合探针也包含这三个权重，用于观察新训练图、旧训练图和验证图。
- `checkpoint_comparison.json` 报告终点减最佳点的项目层面配对统计。
- `checkpoint_comparison.html` 展示全部三方生成结果；`checkpoint_comparison_basic.png` 展示所有基本类别/颜色提示。
- 验证误差最低不等同于生成质量最好，不自动替换默认模型。

评估已排队顺序执行，避免并发加载多个 Qwen 模型挤占显存。


## 最终状态与三方结果

保守续训完成全部 16,000 次额外更新，累计至第 22,000 步；更新序列连续、loss 全部有限，模型与 Adam step 均已核查。最低固定验证误差在第 8,000 步（0.146792），最终第 22,000 步为 0.151797，原第 6,000 步为 0.164229。

227 个固定案例和 157 条拟合探针均完成三方比较。两轮生成评估中的原第 6,000 步输出有 227/227 张逐像素一致，确认比较基线一致。最低误差模型的补充队列最初因脚本写入尚未完成而启动失败；发现后已补跑并核验完成，未将缺失阶段当作完成。

下表为合成 MAE，越低越好。最低 flow 验证误差不等于生成误差最低。

| 固定生成组 | 6,000 步 | 最佳验证 8,000 步 | 最终 22,000 步 |
|---|---:|---:|---:|
| 原核心验证 43 张 | 29.716 | 29.822 | 30.408 |
| 宽范围短名称 64 条 | 43.256 | 43.669 | 44.016 |
| 宽范围详细描述 12 条 | 34.526 | 34.788 | 35.842 |
| 新验证短名称 28 条 | 34.722 | 35.629 | 35.190 |
| 新验证详细描述 28 条 | 29.130 | 29.490 | 30.145 |

宽范围短名称前景 IoU 分别为 0.640、0.639、0.615；终点出现 1/64 个完全空前景，前两者均为 0。最佳点在多数开发验证指标的点估计上优于终点，但不是每项都更好，多数配对区间也跨 0。宽范围详细描述的终点减最佳点 MAE 项目均差为 +1.279，95% 配对 bootstrap 区间 [0.144, 2.519]；这是单训练种子的开发集结果。

另一个固定种子的拟合探针中，新训练图短名称 MAE 为 23.337→22.352→21.424，新训练图长描述为 20.032→19.598→19.787；旧训练图短名称为 18.316→18.620→19.083。因此末点对部分新训练图更贴近，但旧样本拟合和整体泛化没有同时改善。检查过的训练样本仍有明显颜色错误，不能把训练步数增加等同于问题已解决。

本轮保留 `training/best_flow.pt`（8,000 步）和 `training/latest.pt`（22,000 步）。若只在本轮两个续训候选中选择，最佳误差点更稳妥；它仍未证明整体优于原 6,000 步或此前已接受的小核心恢复候选，不自动替换默认模型。

三方图见 `outputs/text_expansion22k_conservative_20261102/checkpoint_comparison_basic.png`，全部案例见同目录的 `checkpoint_comparison.html`；配对统计见 `checkpoint_comparison.json`。最终检查点和优化器审计见 `completion_audit.json`。
